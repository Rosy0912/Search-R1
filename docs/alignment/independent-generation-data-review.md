# Independent generation, data and trainer integration review

Review scope: isolated `baseline_aligned` candidate checkout, production generation/controller/data/config/trainer paths, and the frozen Search-E1 Search-R1 archive. No remote job, active experiment, node, or training state was changed. This is source and CPU-path evidence, not a claim of completed GPU deployment or experimental equivalence.

## Findings

Three integration defects found during review have been corrected in the current source:

1. **Legacy E1 gate isolation.** The first trainer edit accidentally made `_e1_pause_after_five()` depend on `fresh200_gate_enabled`; that would disable the existing E1 gate. The current source restores the original E1 condition and gates only fresh200 with its dedicated switch.
2. **Aligned evaluation protocol identity.** Training obtained `baseline_aligned=True` through the HF denominator binder, while dev/stage/final evaluation did not. Consequently `evaluation.batch_answer_metrics()` still applied the legacy whole-chain legality rule to `val/format_rate`. `SearchRollout.compose()` now stamps the aligned identity for every composed rollout, including evaluation.
3. **Silent dev subsampling.** The first config validator accepted `val_data_num`, allowing a shared-file manifest to pass while the actual trainer evaluated a smaller sampled dev set. The current validator requires train/validation subsampling to be disabled; input admission requires dev512, final51713 and an explicit stage64 identity.

The token reduction discrepancy discovered by the other independent review was also corrected during this review: the aligned actor now matches the archive's masked token mean **within each fixed microbatch**, divided by its accumulation count. It does not average per-sequence normalized losses. The reference KL uses the same microbatch token reduction.

**Resolved retrieval admission:** the candidate now has a mandatory local-loopback retrieval identity gate. It binds pinned E5/corpus/index file identities and actual loaded GPU encoder/index metadata, and compares baseline golden retrieval/reference-token probes before admitting the run. The launcher requires the corresponding baseline identity manifest. Supplying valid baseline manifests and obtaining live passing launch evidence remain execution prerequisites; this review does not claim a GPU deployment or live retrieval result.

## Evidence and limits

An earlier focused CPU run passed34 tests covering the aligned actor, generation, validation, raw native capture and protocol/data modules. The actor's17 tests include20 real AdamW commits at outers1,49,50,200; fatal refusal for input/ratio/reference/gradient/candidate nonfinite; retained0/3/19 prior writes; and an unequal-length microbatch gradient oracle through the actual actor loop. The actor/legacy objective regression batch before the raw-diagnostic extension passed81 tests. Aligned diagnostic forward scans occur only before the first and after the last Adam write of each outer; dedicated forward-count tests prove there are no intermediate full-rollout scans and preserve numerical-fault accounting. A spy test confirms overflow admission happens collectively before exponentiation, without a finite-ratio clamp.

The generation oracle compares actual production manager and rollout methods with deterministic tokenizer/RPC fixtures. The frozen archive was also inspected directly for its rolling-state positions, right-side caps, closed-tag handling and final-generation behavior. These tests establish controller mechanics under the exercised cases; they do not establish native model tokenizer/version identity, actual question-order export provenance, sampling-policy KL on rewritten tokens, retriever process identity, GPU numerical parity, or a trained model result.

Current-profile defaults preserve legacy behavior. The candidate is a separate config and checkout; applying it to an existing run is outside this review and was not performed.

## Bounded raw sampler diagnostic follow-up

The aligned actor now additionally caches the first4 trajectories per rank (at most32 global), at most5 native turns per trajectory, with4096 request-token and500 raw-completion-token limits. It validates native journal hashes, row/snapshot/request identity, selected native probabilities, transported raw tokens, full-support temperature1 sampling and neutral sampler transformations in both caller parameters and a hashed actual enqueued sequence-group proof. Caller settings alone cannot admit an available estimate. HF recomputation uses native request+raw completion IDs and explicit attention/positions, independently of rewritten training actions. Two fixed-slot scans at outer boundaries add at most20 forward calls per rank per outer; padded slots do not enter estimator totals. Every rank follows the same scan layout.

Reported raw-context k3 and negative-advantage raw-token ratio>3 tail measurements describe a bounded cross-backend gap, including baseline backend drift; they are neither a pure policy KL nor the PPO denominator or an update brake. Missing provenance, unsupported sampler transformations, nonfinite raw HF outputs or an oversized diagnostic log ratio produce unavailable diagnostics without changing actual updates. Nonconstant original-trajectory advantages disable only the tail statistic. Raw-context construction, exact bounded forward counts, actual20-write integration and real two-rank Gloo agreement/unavailability were exercised by CPU tests. No native GPU or live experimental diagnostic value is claimed.

The raw-diagnostic helper now has20 passing CPU tests, including the actual `DataParallelPPOActor._forward_micro_batch()` probability path with a small causal HF fixture and a manual selected-token log-softmax oracle. The producer adds the actual enqueued-group proof without changing sampler calls, and its5 capture tests cover producer-callback→helper integration, transformed actual group rejection, unavailable group APIs, caller-only metadata rejection and unchanged generated tensors. The owner of the overall change is running the final combined regression suite separately. Actor/helper source is frozen for that run.
