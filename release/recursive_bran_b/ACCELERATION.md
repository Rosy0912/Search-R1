# HKUST5 B continuation and acceleration

Latest human authorization in experiment A explicitly applies these speed changes to B. Eval, full state saves, detailed tree/trajectory records are only at outer5/50/100/150/200. Other outers retain training metrics, essential optimizer safety/error records and in-memory algorithm state. The initial10 healthy-outer goal remains; there is no extra dev10 endpoint.

The native emitted FP32 behavior mu remains the PPO denominator. Per-action HF recomputation is skipped only when the native emission contract applies and sampling consistency diagnostics are disabled. A separate opt-in skips the full-batch HF beta pass under the zero-reference-KL behavior-mu contract. No beta is fabricated; unavailable beta comparisons are null. Current gradient forwards and subset safety checks remain. Validated native temperature-one metadata is carried explicitly.

The vLLM policy cache is bounded by actual committed optimizer calls and scheduler step. It synchronizes the first sampling call only, retains the same version thereafter and releases before HF/reference/update/save or on errors. Each call retains the original training/sampling CUDA RNG handoff and KV lifecycle. RPC wall counters include backend/sync work; they are not pure decode time.

`recursive_b_schedule_resume.py` supports a single cold transition from actual original source3da/config95 complete4 or5, same four ranks, complete model/Adam/scheduler/RNG and driver order/cursor. Only the two explicit schedule lists change in YAML. Every rank hashes the full actual parent state, checks its logical digest, restores the FSDP layout and checks the complete loaded state against the parent. It also restores the separately captured vLLM sampling CUDA stream; this does not claim bitwise vLLM executor equivalence. Future protected native checkpoints include their own sampling-stream supplements.

`capture_sampling_rng.py` uses the existing exact owned worker callback API, queued during actor update. It refuses changed owner/source/counters, a committed checkpoint or a different scheduler boundary. It copies the CPU byte state without a random draw; full state bytes stay remote. Initial read-only API preflight mistakes were preserved and did not alter training. Capture is not accepted until all four actual worker results and matching complete checkpoint exist.

`resume_hkust5.py` requires an explicit parent technical terminal, all original owned processes absent, immutable binding/config/source and a new output directory. The ordinary four GPU leases, hardware UUID/free/foreign checks and current remote retriever gate remain mandatory. No historical OPSD or HKUST4 waiter is restarted. No active deployed source is hot-patched.

Targeted checks cover cache lifetime (4), actual mu loss/gradient/one Adam update plus retained safety and refusal contracts (3), sparse-only YAML changes and independent sampling RNG byte restore (3). Local macOS has no Torch/omegaconf runtime available for the numerical tests; they must run in the original Node environment with CVD empty. AST and cache mock tests can run locally. CPU checks do not establish GPU speed or full-round numerical equivalence. A complete new GPU outer and real next advancement are required before acceleration acceptance.
