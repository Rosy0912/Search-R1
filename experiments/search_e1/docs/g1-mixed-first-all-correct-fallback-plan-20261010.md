# Search-G1：混合组优先采样与全对候补执行方案

状态：方案已确定，交其他agent实现和运行；本线程未启动训练、未热改正在运行的源码。日期：2026-10-10。

## 当前有效人工要求

- 最终每轮入训512个题组，保持既定每题G条完整轨迹。
- 优先只收有正确也有错误的组；遇到全对/全错换全新题，不重采原题。
- 每轮最多尝试2048道不同候选题。到上限仍不足512组时，只从未通过混合筛选的全对组补齐。
- 全错组绝不用于候补；不得用零优势行、重复题或缺失轨迹填数。
- 此要求取代无限采样直到512个mixed的上一版方案。NLL/EMA/h设计单列，不因为本次采样改动自动改损失、学习率或其他科学设置。

## 固定定义

对一题完整生成G条轨迹，使用原严格gold EM评分器，得到 \(C_i\in\{0,1\}\)。非法输出按原严格规则为0；不能用shaped reward阈值代替正确性。

- `mixed`：\(0<\sum_iC_i<G\)，优先入选。
- `all_correct`：\(\sum_iC_i=G\)，本轮候补。
- `all_wrong`：\(\sum_iC_i=0\)，拒绝且禁止候补。
- `incomplete/error`：尚未完整生成或评分，不能分类为上述任一组，也不能进入训练。

“失败的全对组”指未通过mixed筛选，并非推理失败。每题必须有原G条真实轨迹；不能删除正确响应、拼接别题响应或伪造失败来制造mixed。

当前已核旧Search-G1使用G=5。执行者与选定baseline对齐G，不从本计划静默改成4。若启动前已明确采用拟议G=4，对照组也同为4；G4最终2048条，G5最终2560条。

## 选择与更新流程

1. 每轮开始冻结student/采样模型、原probe版本、生成预算与参数，并保存候选顺序和随机状态。整个填充过程不更新模型/Adam/probe。
2. 依预先确定的随机数据顺序抽候选题。稳定question ID和规范化原题内容身份同时去重：本轮已尝试的题，无论接受还是拒绝，均不再次生成。跨轮沿原数据epoch规则，不额外强加全训练永久不重复。
3. 先为新题保留candidate ordinal及题目配额，再生成G条。异步提交也不得超过2048道独立题；重复源题在生成前去重，不作为新候选充数。
4. 完整严格评分后，mixed加入优先池，all_correct加入候补池，all_wrong只保留远端审计。worker完成顺序不作为选择顺序；按候选ordinal消费。
5. mixed达到512时，选择预定顺序前512组，停止派发新候选；已在途的生成正常收尾，真实成本照计，额外组标记未入训。不能将其旧策略轨迹转到下一轮冒充fresh。
6. 若2048道完整候选处理后mixed数M<512，缺口D=512−M。先保留全部mixed，再从all_correct按原候选顺序选前D组。禁止按reward、probe分数、响应长度或生成耗时择优。
7. 最终成员恰为512个不同题组；按原candidate ordinal组装，维持原trainer的打乱/分发规则，避免把mixed固定排在候补之前。之后才计算原Search-G1奖励及原组优势，执行原GRPO更新。

候选题顺序预先随机且冻结，因此“取前D个全对候补”不新增reward择优。批量过采时只按预定顺序选前512个mixed，不能利用异步返回速度挑题。

## 训练保持什么

- 最终512×G轨迹，原mini/micro、ppo_epochs、loss mask、loss分母和优化器机会安排不变。
- 每个入训组完整使用原R与原组均值/标准差，包括候补全对组。不自动将候补A设0，不重新缩放不同来源组，不给其额外奖励。
- 基线mini128/ppo_epochs1时，G4为16个更新机会，G5为20个；安全检查拒绝写入时按实际Adam报告。
- 原学习率、KL、entropy、clip、token reduction、检索/生成参数继承已选baseline。此次只改候选选择及候补策略。
- NLL若另作h消融，保留其冻结行为概率、EMA历史和原mask定义；所有h组使用同一候选上限与候补规则，不自动新增teacher forward。
- 正式验证集完整同条件评分，禁止只保留mixed题或fallback题报告EM。

全对候补保留原shaping，所以“小探针差异被小标准差放大”的机制在候补中仍存在。此策略优先mixed并限制生成量，不声称完全消除该机制；最终batch命名为“mixed优先＋all-correct候补”，不能称全mixed。

## 保底成立条件与不足处理

令2048候选中的mixed数为M、完整全对数为A。能组成512组的必要条件是：

\[
M+A\ge512.
\]

若满足，最终组数严格为512；若不满足，规则本身无法补齐。例如2048题都全错时，不存在合法候补。执行者必须记录 `INSUFFICIENT_ELIGIBLE_GROUPS`、保存真实进度并不进入优化器更新；不能用全错/重复题补位、降低512目标或擅自突破2048上限。该终态不是模型OOM或伪造训练完成。

唯一题库在2048前耗尽或采样故障也需明确分类。资源中断保存candidate ordinal、去重集合、完整组池、在途/不完整组、各worker实际采样RNG及模型身份；恢复必须继续同一冻结轮次并证明状态，不能从0重跑伪称续采。

## 实现验收例

| 输入情况 | 预期 |
| --- | --- |
| 上限前已有512个mixed | 选择512mixed，无候补，停止新增派发 |
| 2048题：M=400，A≥112 | 400mixed＋按序112all_correct，恰512组 |
| 2048题：M=0，A≥512 | 512all_correct候补，真实报告mixed=0 |
| 2048题：M=400，A=100 | 合格组不足；无优化器更新，不引入12个all_wrong |
| 2048题：M+A恰为512 | 全部合格组入选，恰512组 |
| 源题重复、worker乱序、批量超过目标 | 轮内唯一，选择由预定ordinal决定，额外生成成本保留 |
| 组有少于G条/严格评分失败 | 不入选，不冒充all_wrong，记录真实故障/未完成 |

执行者先在独立副本实现与验证这些行为，提交推送并核验最新源码，再启动实验；保留原冻结runtime及旧日志，不热改活动训练。启动后需复核至少两次真实进展并确认一整轮正常完成。用户未在本线程要求启动，本方案不代表已运行。

## 预算与解释边界

最多2048×G候选轨迹，即原512×G的4倍生成量上限；早停、在途和故障按实际记录。最终训练轨迹量相同不等于总计算量相同。

旧第100/120轮的混合比例若作线性示意，2048题分别约380/332个mixed，需132/180个全对候补；这不是新训练实测或ETA。不同student、G和题分布会改变接受率。

该策略改变题目/轨迹分布。效果比较必须报告相同训练更新预算以及额外生成预算；不能只因EM变化就认定探针被hacking或置信度加权已有效。
