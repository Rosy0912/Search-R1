# 原 R（BF16）与当前 P＋R（FP16 实现）的实际轨迹比较

2026-10-10。仅对已有 HKUST1 输出做 CPU 分析，未新增模型生成、训练或 GPU 任务，未修改正在运行的科学配置。原始题目、答案、生成 token、HTTP 与 checkpoint 留在 HKUST；本地/Git 仅保存代码和小型汇总。

## 先说明实际精度，以及与用户意图的区别

用户最新明确表示希望保持 BF16。当前已运行的 P＋R 却沿用了此前七组执行说明中 `fp32_master_fp16` 的 P 定义。代码符合此前 P 定义，不能据此说它符合用户此次明确的 BF16 意图。当前结果应标为“FP16 实现”，不能改名为 BF16 或热改配置后混接曲线。

P 是数值实现方案，不是新的蒸馏损失或匹配算法。实际 C1 和原 P 的区别：

| 环节 | C1 | 原 P / 当前 P＋R 的 P 部分 |
| --- | --- | --- |
| 冻结基座参数保存 | BF16 | 从原 source100 直接加载 FP32 |
| 可训练 LoRA 参数、梯度累积、Adam 状态 | 已经是 FP32 | 仍为 FP32 |
| 主 transformer/head 计算 | BF16 | FP16 autocast |
| LoRA A/B 分支计算 | FP32，结果转回基座输出类型 | FP16 autocast；FP32 主参数接收梯度 |
| norm 内部、log-softmax/KL | FP32 稳定计算 | FP32 稳定计算；norm 出口转 FP16 |
| 训练前生成 rollout | BF16 合并模型 | FP32 基座＋FP32 adapter 合并后一次转 FP16 |
| 同步梯度缩放 | disabled，scale=1 | FP16 scaler；溢出全 rank 重试，不推进 Adam/cursor |
| 正式固定512评测 | BF16 基座＋FP32 未合并 adapter | 完全相同的正式协议 |

C1 的实际 rank0 dtype 日志也证实：base q_proj BF16、LoRA A/B FP32、embedding/norm/head 出口 BF16、scaler disabled；实际采样 worker 为 `torch.bfloat16`。所以不能把两者简化为“BF16 推理 versus FP32 推理”，也不能把 P 说成只是“原来低精度 LoRA 更新修成 FP32”。

P 与 C1 的 LR1e-6、reverse KL、教师冻结、clip10、轨迹内 token mean 后全局 pair mean、优化器和 LoRA 配置相同；P 本身不改变 C1 的 D 选择。当前 P＋R 才另外采用 R 的题内五轨迹均匀 D 选择，包括 B。保持 BF16 计算/采样并保留 FP32 保存/合并，需要明确的独立配置；已有 FP16 结果不能代表该设置。

## 第一轮：尚未做任何 Adam，精度路径已经改变采样

两组共同源100、同初始504 adapter、同512题×5、同 rank seed42–49。初始 prompt 的原 token IDs 在2560个槽上完全相同；使用的是原生成 IDs，未重新 tokenize 冒充原生成轨迹。

- 2517/2560 在第一次生成调用就出现原生成 token 分叉；另外41在第二次调用分叉，仅2条全部原生成 IDs 相同。
- 2559个两边均执行首搜的槽中，1852个首 query 不同；其中1407个首搜文档 ID 也不同。
- 707个首 query 相同的槽，文档 ID 和 content 全部相同；704个完整JSON相同，另3个仅 score 有至多2.38e−7的微差，原 context 构造不使用 score。不能声称这3个完整JSON相同。
- 全部轨迹最终正确性：162条 R 对→PR 错，178条 R 错→PR 对；其中162个丢失里160为合法最终答案 gold mismatch、2为最终协议无效。

以上是更换数值路径后的实际随机采样差异，不是固定随机数消费下的 logits 因果实验。相同 seed 不保证 dtype/活跃 batch 改变后每一步消费相同随机数；没有存储可供重建每个生成决策的完整 processed logits。本结果不能给出某个 CUDA 算子是分叉根因。

## 成功总数略升，成功覆盖和监督构成却改变

| 第一轮指标 | R：BF16 | 当前 P＋R：FP16 |
| --- | ---: | ---: |
| 正确轨迹 / 2560 | 1280（50.00%） | 1296（50.625%） |
| 五条全对题 / 512 | 184 | 203 |
| 五条全错题 / 512 | 185 | 199 |
| 部分正确题 / 512 | 143 | 110 |
| 至少一条正确、可训练题 | 327 | 313 |
| 被选择 D 已正确 | 252 / 327（77.06%） | 265 / 313（84.66%） |
| 被选择 D 错误 | 75 | 48 |
| D 与 B 为同一 sibling | 58 | 67 |
| 本轮实际 Adam 更新 | 11 | 10 |

可用集合中33题从 R 有成功参考变为 PR 无成功参考，另19题反向进入。共同294题的随机 D sibling 编号全部相同，说明随机选择规则没有改，但被抽中的具体文本和成功参考已经改变。

这一样本的直接发现是：PR 正确轨迹总数略高，但成功更多集中在五条都答对的题；全错题也更多，纠错 D 更少。它支持“精度路径改变探索覆盖和监督组成”的解释，尚不证明该变化造成后续验证退化，也不证明五条全错题在语义上一定更难。

## 前10轮与固定验证结果

前10轮对应题序相同，之后策略已经各自更新。因此这里描述精度设置＋在线数据/权重反馈的整体路径，不能把每个后续差值当作纯采样精度干预。

| 前10轮累计 | R | 当前 P＋R |
| --- | ---: | ---: |
| TRAIN正确轨迹 / 25600 | 11964（46.7344%） | 12326（48.1484%） |
| 可用 pair 曝光 | 3030 | 3002 |
| 错误 D / 正确 D | 630 / 2400 | 530 / 2472 |
| 有效监督 token | 547564 | 512724 |
| 实际 Adam | 99 | 99 |
| 曝光加权 raw / post loss | .524301 / .515907 | .536250 / .521936 |
| 第10轮 raw / post loss | .521840 / .512258 | .509306 / .494466 |
| 同协议固定512正确题 | 240（46.875%） | 232（45.3125%） |

两组都是99次 Adam；第一轮11 versus10的差异在之后轮次抵消，不是总更新预算少1。错误 D 曝光减少100条（15.87%），有效 token 减少34840（6.36%）。Loss 来自不同的生成历史和数值计算路径，不是同一响应上的纯精度误差。

固定512差值由15题丢失、7题新增构成，保留225、仍错265；NQ丢6/增2，Hotpot丢9/增5。15个丢失全为协议有效的答案错误，均执行过搜索；8题搜索次数相同、5题更多、2题更少。净差−8题/−1.5625pp；按题 paired bootstrap10000/seed42 的95%区间[-3.3203125,+.1953125]pp。

因此，现有证据说明训练输入和学到的策略确实不同；不是固定512评测时偷偷换了 dtype，也不是所有生成质量指标都下降。尚未把采样端变化、teacher/student 训练计算变化与后续在线累积的贡献单独分离，不能据此宣布 FP16 或 FP32 保存是最终退化根因。
