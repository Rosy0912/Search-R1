# Online Search-E1 OPSD from archive100

This is a new standalone control/learning implementation. The old 305-file scientific runtime stays byte identical. No GRPO stage is launched and no old GRPO/OPSD Adam is restored. Source100 remains the frozen teacher. The native prompt, response mask, strict reward, generation budget and `core.mine_pairs` are reused from the exact frozen runtime.

`prepare.py` is CPU only. It writes an explicit candidate configuration and may copy exactly the bound 305 source files into a new runtime. It does not approve storage, retire the resident retriever, start CUDA, or alter a live process. `component_clip`, `outer_iterations`, storage approval and eight-card execution authorization remain explicit HOLD conditions until filled from actual human decisions and bound receipts. The target LR is 5e-6, trajectory mean, micro1, global32, LoRA16/alpha32, AdamW original defaults, no scheduler/warmup, norm clip1. Component KL clipping is a separate pending decision.

## Outer rounds and actual updates

Each outer round fixes the current raw latest student, selects 512 unique TRAIN questions from a seed42 deterministic permutation stream, then samples five siblings per question on eight workers (64 questions/320 trajectories each, seeds42 through49). The selection cursor records cycle/offset and any consumed duplicate at a permutation boundary. Selected questions may not equal heldout validation IDs or exact question text; overlap is rejected rather than silently substituted. Validation never supplies sampling rows.

Generation uses the original vLLM function: temperature1/top_p1, 8192 context, 500 tokens per turn, five turns, four executed searches, top3 retrieval and 480 observation tokens; final forced-information behavior and stop tags stay unchanged. The admitted 18004 oracle can share only GPU7 under the resource gate. XFORMERS, eager, BF16, utilization.85 and22671 GPU blocks are explicit physical settings. The logging wrapper returns the exact original vLLM output objects and saves actual prompt/generated token IDs, native text, stop reason and timings in private per-worker traces. It does not substitute teacher samples or reconstruct token IDs from response text.

The first sampler loads raw source100. Later samplers load a CPU BF16 PEFT merge of source100 plus the latest completed raw adapter. This is the original E1 merge method; merged BF16 arithmetic need not be bitwise equal to unmerged training. The chosen identity binds the exact previous checkpoint, cumulative Adam count and adapter tensor digest. There is no best-checkpoint selection. One full CPU SHA scan binds sampling model files, then each actual LLM load and generation checks file inode/size/mtime/ctime continuity before/after. Merged cache files are never silently reused after metadata changes.

Native mining keeps at most one pair per question: min-success search/token reference, fail-preferred maximum normalized full-string rapidfuzz Levenshtein student, native first tie, all-success fallback, all-wrong skip. Full2560 trajectories are required before mining. Record P before context/mask checks and K after checks, 0<=K<=P<=512. Training makes ceil(K/32) actual Adam calls, including a partial tail with its real denominator; K0 makes zero calls and no scheduler progression, but still saves a complete initial/current state.

## Resume and artifacts

Controller CLI:

```
E1_RUN_ID=<fixed config.run_id> python controller.py --config CONFIG --config-sha256 SHA --run-id RUN_ID
```

Fault restart adds `--resume` with the same immutable configuration SHA and same run ID. It reuses completed sampling/immutable outer inputs and loads that outer's highest complete checkpoint/cursor through `trainer.py --resume-checkpoint PATH --resume-checkpoint-sha256 SHA`. Already committed Adam updates are not replayed; an incomplete pending update is not counted. `outer_start_updates` is the outer manifest's cumulative count before training, even when fault restart restores a later update from within that round. Completion counters use that original start, not the resumed intermediate count.

Every checkpoint has actual adapter files and eight complete Adam/RNG states, source/config/run identities, encoded/order/pair input proofs, pair cursor, cumulative updates/exposure, and adapter/optimizer tensor digests. A manifest is committed only after actual state files. `checkpoint.py` independently validates immutable files and protocol/coverage; it does not deserialize Torch moments or claim numeric equality from an `equal_optimizer_steps` Boolean. Trainer restore verifies each state's rank/cursor/RNG/Adam and gathers actual digests; the root's independent five-real-update acceptance also reads actual states. A completed checkpoint export without full Adam/RNG is rejected.

All raw rollouts, search observations, generation traces, pair identities and every valid-token training loss are retained privately. Top32 probability dumps retain the first8192 valid positions per outer round by default; this is an ordered prefix rather than a population sample. Explicit cap0 disables only top32 dumps while retaining every scalar token loss. These are actual online losses, unlike earlier posthoc fixed-trajectory probes. Full-vocabulary dumps are not promised. Git receives source/schema/compact proof only, no question bodies, token data, model weights or environments.

The authorized rolling policy retains latest two complete checkpoints plus initial/update1/update5 and every outer-end checkpoint. Only SHA-verified, unprotected, complete checkpoints from this new exact run may be pruned; full manifest/hash tombstones persist. No pending directory or old experiment is deleted. Latest two completed CPU merge caches are kept; older completed caches can be reconstructed from protected outer-end adapter plus source100, with original merge file hashes/recipe retained. Actual byte equality of a future regenerated cache must be checked, not assumed. No pruning runs before explicit retention/storage/publication acceptance. This prevents unbounded 200 full merges or per-step optimizer archives while keeping resumable scientific state and private diagnostic data.

## Lifecycle and admission

`acceptance.require_launch(config, phase, run_id, owner, known_children=[])` is called before every launch and during waits. Exact phases are `sampling-start`, `training-start`, `cpu-merge`, `sampling-running`, `training-running`. Start/merge phases require no owned GPU jobs and 20GiB direct free per card. During a running phase only cards occupied by identity-bound owned workers may use the1GiB running floor; cards not yet occupied keep the20GiB floor. Foreign processes are never stopped or accepted as owned.

`acceptance.require_owned_release` uses the published V2 same-UID environment/argv/output/parent-chain scanner. Empty GPUs or a missing parent PID alone do not prove termination. Actual `wait()` return codes must all be0; GPU UUID mapping, direct memory and full descendant release are checked before the next stage. Child registration happens immediately after Popen. Any launch/ownership/read error locks FAILED/UNCERTAIN, preserves the exclusive lease, waits for actual owned termination without sending signals, and forbids another CUDA phase. The external memory observer is root-launched under an independent run marker, never a controller child to be mistakenly exempted.

In addition to the new online lock, the controller acquires the four exact existing K1 experiment leases specified in `resources.shared_gpu_lease_paths`, in a fixed order and without blocking. These cover debug, native512, counterfactual and archive100-OPSD controller scopes. All locks stay held through an uncertain child-release wait. The resource-transition proof also binds that the latest human online priority supersedes the unstarted M3/M4 GPU launches; neither stale heartbeat instructions nor a separate output directory authorize concurrent use.

The source publication receipt binds pushed/readback search-e1 commit and every helper SHA. Storage binds the exact future output root, actual mount/cross-node identity/retention or an explicit human HKUST local exception and durable synchronization policy. Existing-parent disk checks permit a not-yet-created fresh output directory. Source/runtime/helper identities are separately bound. The live eight-card transition receipt must show the previous resident0–3 job safely preserved/retired; this code cannot perform that retirement.

Five accepted actual updates are a milestone within the same full run. The controller keeps running afterwards; there is no five-step test followed by a fresh scientific restart. Outer rounds and cumulative optimizer calls are separate counters. No GPU execution or production numerical equivalence is established by the CPU fixtures.

The independent CPU memory observer uses a separate nonempty `E1_RUN_ID`, a separate supervisor, and files under `paths.receipts` outside `paths.output_root`. Start it with `--config CONFIG --output LIVE_REPORT --binding-output IMMUTABLE_BINDING`. Its static binding captures actual PID/UID/starttick/run and the published observer source SHA. `verify_five_updates.py --memory IMMUTABLE_BINDING --memory-sha256 SHA` binds that static receipt rather than an old SHA of the changing live report. Only after all adapter/eight-rank CPU checks does acceptance read a stable current atomic report, recheck the observer process, require freshness within30 seconds, validate the eight physical UUIDs and historical direct-memory limit, and save a separate exclusive snapshot. A long CPU inspection therefore does not invalidate healthy ongoing memory observation; a stale/stopped/reused observer still fails.

This implementation has not launched a GPU experiment. The referenced human specification explicitly leaves KL component clipping unselected and does not define a new outer-round budget; those two science decisions remain unresolved. The verified same-cluster shared-output requirement or an explicit HKUST exception also remains unresolved. The startup template cannot authorize any of those choices by itself. Source100-only initialization, inherited trajectory mean/micro1, target LR5e-6 and fresh online512x5 are already fixed. Normal gradient clip1 is retained independently of the pending KL component clip.

## Private HTTP and protocol diagnostics

The native rollout module alone receives a requests namespace proxy; the installed global requests module is unchanged. Each actual POST keeps its URL, original argument objects, timeout300, original Response object and exception behavior. A separate private per-worker JSONL retains complete queries, full response JSON and body, document IDs/scores/content, request/generation-call identity and timing. It records the original observations before the native480-token truncation. Worker completion binds the HTTP file SHA and request count; the controller validates all eight private trace identities before accepting an outer round. Logging failures cannot replace a Response or original network exception, and they reject completion. CPU fixtures also execute the unchanged frozen rollout flow with fake inference/HTTP and prove equal trajectory rows and POST calls; they do not claim live GPU equivalence.

Every original trajectory additionally records strict parsing of its last authored action, strict reward, native termination and executed-search count. Literal tag balance for each policy span and joined policy text is explicitly diagnostic only; it neither changes native reward nor filters mining. Counts are saved separately in each worker receipt and outer-round sampling statistics. The generator's `termination=answer` marker is not treated as proof of a valid terminal answer.

Scoring remains the existing305-file dependency at `runtime/upstream/Search-R1/search_r1/qa_protocol.py`, SHA9a825a7b222b5a3fd2c1de7f63ed38e157258fcf858e773ff64c963a4b6daddd. The controller sets PYTHONPATH exactly to `runtime/upstream/Search-R1:runtime`. CPU runtime verification, sampling-worker import and aggregate/resume scoring invoke the bound `verify_scoring` helper before importing native core. No duplicate scorer or new scoring rule is created. CPU fixtures accept `OPSD_ONLINE_TEST_RUNTIME` for the existing node runtime and use its nested upstream dependency, without copying model weights or scientific source into the helper.
