# PR100 online OPSD training

This independent namespace implements the 2026-10-10 human request: C1 plus P precision and R random D,100 online outers from the same accepted archive GRPO100 source weights and original common zero-B504 adapter, fresh Adam. It does not reuse a trained P/R/J adapter or GRPO Adam.

Science is fixed by one immutable `opsd-pr100-config-v1` config and one32hex training run across all ten evaluation boundaries. PR uses LR1e-6 constant/no warmup, upper vocabulary component clip10 retaining negative components, teacher-only reverse KL with both p and logp gradients, unit pair weights, trajectory-internal valid-token mean followed by actual global pair mean, global32/micro1/eight ranks, LoRA16/alpha32 and the original optimizer/clip/scorer/budgets. B remains the strictly correct trajectory with least executed searches, then least tokens and original source order. D is unbiased deterministic uniform among all five siblings including B. All-five-wrong questions remain skipped. There is no M mixture or W correctness weighting.

P precision is unchanged: actual FP32 model/master adapter/gradients/Adam moments, FP16 main computation and sampling, explicit FP32 stability operations and synchronized scaler/retry. CPU merge starts with FP32 base plus latest FP32 raw adapter, merges once and casts once to FP16. The proven PEFT0.13.2 outer-old pre-setter FP32-storage repair is integrated before the exact setter;504 input/digest/current-unchanged checks and per-rank receipt remain. Frozen teacher/outer-old guards remain, even though PR's target is teacher only.

The100 cohorts are the first51200 elements of the original isolated `random.Random(42).shuffle` TRAIN169103 permutation. `prepare_bundle.py` requires the first ten cohort rows and full permutation digest to match the original ten-group frozen selection exactly, and all100 cohorts to be disjoint from heldout512 by ID and exact question text. No drops/replacements occur.

## Entry and boundary

```text
CUDA_VISIBLE_DEVICES='' E1_RUN_ID=<fixed training run> <original env python> -B <helper>/controller.py --config <immutable config> --config-sha256 <SHA> --run-id <same run> --until-outer 10
CUDA_VISIBLE_DEVICES='' E1_RUN_ID=<same run> <original env python> -B <helper>/controller.py --config <same config> --config-sha256 <same SHA> --run-id <same run> --resume --until-outer 20
```

The actual option is separated as `--until-outer 10`, then20,...100. It is mandatory; the config remains `scientific.outer_iterations=100` throughout. The completed prefix is checked and not regenerated. Latest complete rank Adam/RNG/scaler/cursor/order state is restored before the next outer. At each requested boundary all owned GPU descendants release, and `runs/boundaries/outer-00010.json` etc bind completed outers, cumulative real Adam updates, latest raw checkpoint, last outer-complete and resource-release proof. Status is `TRAIN_BOUNDARY` through90; only100 is `TRAIN_COMPLETE`. A boundary receipt does not prove the training parent returned0; the periodic supervisor separately records actual wait0 before launching native512 evaluation. Evaluation never touches or replaces the optimizer state or the training adapter.

The controller locks `base/online-experiment.lock`, the original five `resources.shared_gpu_lease_paths`, and the new `study_lease_path`. The periodic supervisor holds a separate pipeline lock and has a narrowly admitted CPU role: exact `opsd_pr100_periodic_v1/supervisor.py --pipeline-config <ref> --pipeline-config-sha256 <SHA>`, published source/manifest and live PID/UID/starttick/argv/run binding. Memory observer has a separate marker and reads the same immutable training config. No historical seven-group authorization is accepted.

The latest human requests compact output. Top32 and full-vocabulary NPY dumps are disabled; autonomous teacher-generation diagnostics are disabled (the frozen training teacher remains enabled). Necessary sample/mining inputs, HTTP/retrieval traces, generated IDs and every valid-token compact pre-update loss remain for same-run recovery. Key initial/update1/update5 and all100 outer-end states are protected, with the latest two complete states retained. Non-key/non-end state payloads are reclaimed only after a newer complete commit; every original checkpoint manifest and an explicit non-resumable prune receipt remain. The resume scan skips explicitly pruned non-key state entries. All retained states and logs stay on HKUST remote storage. No tensors or raw experiment data are prepared on the Mac. Retention is `keep_key_and_resume`; original outer-end states and essential provenance remain. Only this new namespace's completed outer `merged-model-cache` is reclaimed after native accepted outer-complete, actual trainer wait0 and full GPU release. Immutable merge manifest/request/child/parent, outer-start checkpoint, all raw generation/token evidence and all states remain. An intent plus accepted reclaim receipt records exact original model-manifest SHA and bytes. Current/incomplete caches and any old experiment directory are excluded.

`prepare_bundle.py` is CPU-only and emits a candidate lacking new human/scoped gate receipts. Root fills those exact receipts after publication, then the separately published periodic supervisor orchestrates ten training/evaluation cycles. This namespace does not itself start a GPU job.
