# Strong-terminal gate for the original posthoc replay

This independent namespace adds an immutable CPU preflight before the already
published analysis replay. It does not modify original training, recovery,
analysis/scoring code, model parameters, sampling budget, locks or resource
ownership rules. It is not a new training or generation experiment.

**Future execution only:** while any of the four training arms remains active,
the actual strong terminal and100-outer coverage inputs cannot satisfy this gate.
No GPU operation is performed by `preflight`. Only after that exact evidence is
available does `run` call the original `replay.run` directly in the same PID.

## Why same process

The original replay release scanner treats another live process carrying its
run marker as owned. A subprocess wrapper parent would remain live and block
release. This wrapper imports the original package in an isolated source-only
namespace, preserving each original module's actual `__file__`, then directly
calls the unchanged original function. It never replaces scientific functions.

The original leaf also checks its real parent's argv for the exact original
`replay.py` path. Therefore the new CLI must include the explicit
`--original-replay-entry ORIGINAL_HELPER_ROOT/replay.py` argument. This is a
published original-source input pointer, not a claim that the new entry filename
is the old entry; actual argv is never fabricated or modified.

## CLI after publish and deployment

```text
E1_RUN_ID=ORIGINAL_PLAN_ANALYSIS_RUN_ID CUDA_VISIBLE_DEVICES='' PYTHONDONTWRITEBYTECODE=1
ORIGINAL_ENV_PYTHON -B NEW_GATE_ROOT/gate.py
  --request IMMUTABLE_GATE_REQUEST --request-sha256 EXACT_SHA
  --original-replay-entry ORIGINAL_ANALYSIS_ROOT/replay.py
```

No extra parent subprocess is introduced. The original function retains its
study-sequence/shared/study/four-online/replay locks, fresh UID/PID ownership,
oracle18003/GPU4–7 UUID and memory.free checks, original four leaf workers and
actual wait/release checks. The wrapper only accepts its eventual complete
artifact after all4608 posthoc rows and release; it does not claim autonomous
generation or new samples from teacher-forced replay.

## Request schema

`schema=opsd-signal-posthoc-replay-gate-request-v1`:

- `gate_source`: `helper_root`, published `source_manifest`, `publication` for this
  independent prefix. Its actual `gate.py` path must match the current module.
- `old_plan`: the original immutable `opsd-signal-heldout-replay-plan-v1` reference.
  All original plan bytes and source/publication remain unchanged.
- `study_manifest`: original four-arm manifest.
- `strong_terminal`: accepted `opsd-signal-weight-driver-terminal-v1`, actual same
  retained tmux pane status0/release, binding the original native completion.
- `native_study_completion`: original four-group-terminal reference, still passed
  to original replay. A strong terminal object never substitutes its schema.
- `configs`: map of four original immutable config refs.
- `final_checkpoints`: map of four actual committed raw outer24 CP refs, identical
  to initial coverage and endpoint25; cache/best substitutes are forbidden.
- `endpoints`: original commonzero plus four15/four25 child refs, exactly the
  original plan's nine endpoints and the coverage report's nine child refs.
- `bank`: same already frozen source100 commonzero B bank, exact original ref.
  Do not refreeze or dynamically select references after observing outputs.
- `initial_coverage`: actual assembler `actual_stdout`, report `output`, recorded
  `execution`, `helper_root`, `source_manifest`, `publication`. The execution must
  bind the true CLI stdout; its `output` field resolves the actual coverage
  artifact. Require `coverage_accepted=true`, four arms/100outers/256000 TRAIN
  slots/4608 native slots, explicit configs and final raw states.
- `replay_output`: a new authorized remote analysis attempt for original replay.
- `preflight_output`: a separate new remote analysis audit file, outside
  `replay_output`. Writing it must not precreate the original replay directory.

Initial coverage may have `final_accepted=false`: final requirements include the
heldout relationship report generated by this replay. Requiring finaltrue before
replay would create a dependency deadlock. Missing100/4608 coverage, unknown
supervisor wait, other configs/raw weights, or missing source publication remain
fail-closed; permitting finalfalse does not relax those checks.

The preflight calls no HTTP/GPU/Slurm command, no signals, no Torch, no model and
no RNG restoration. It only reads SHA-bound evidence and source bytes and writes
its own new small audit. Actual fresh GPU/process admission remains entirely in
the unchanged original function after acquiring original locks.

## CPU fixtures

```text
CUDA_VISIBLE_DEVICES='' PYTHONDONTWRITEBYTECODE=1 PYTHON -B -m unittest discover
  -s experiments/search_e1/control/opsd_signal_weight_replay_gate_v1
  -p test_gate.py -v
```

Small synthetic evidence fixtures test same-PID invocation without Popen,
finalfalse dependency handling, actual stdout/report binding, strong wait0,
original argv/source path, cache/raw identity and independent output paths. A
tiny synthetic replay body is used only to test invocation, not original GPU
execution. CPU fixtures and publication never mean the future replay has run.
