# Same-study first15 evaluation recovery

This external namespace repairs a CPU evaluator boundary failure, not a training
or model failure. The exact released G_POS attempt completed15 online outers,
150 Adam updates and4568 pair exposures. Its evaluator actually exited1 after
the native `gates.Hold` raised when the continuously updated memory receipt
changed between SHA calculation and read. All old eight workers later became
absent naturally, but their missing wave1 actual waits remain `UNKNOWN`.
Their512 partial/formal-slot files do not constitute an accepted evaluation.

No original00fec71 source, original98b9326 recovery source, four scientific
configs, runtime305, source100, trained checkpoint or token-loss record is
edited. `trainer_launcher.py` is byte-identical to the already accepted98b
FP32 named-outer-old storage repair. The same study and group run resume through
the original controller; its completed0..14 checkpoints are revalidated and
its pending15 evaluation is rerun at the identical CP150. No completed Adam,
training sampling or teacher diagnostic is repeated by this repair.

## Technical dispatch

`entry.py` dispatches only original exact controller, four-rank trainer and
native evaluator commands against the four pinned config path/SHA pairs.
Evaluation is restricted to native15/25 endpoints and the actual raw end
checkpoint in `training/outer-complete.json`; zero reuse is unchanged. The
actual kernel argv includes `--original-entry ORIGINAL_HELPER/evaluation.py`.
The wrapper validates that real token and its original byte hash and executes
that original file through `runpy`. This satisfies the unchanged worker's
actual-parent source check without falsifying `/proc` or substituting science.

Only the original evaluator `boundary` is wrapped. A native `gates.Hold`
retries the entire boundary after1 second, retaining the original evaluator
leases and every original SHA, source, UID, observer, oracle, UUID, memory,
ownership and release gate. Other exception types propagate unchanged.
Original native worker generation, seed, scorer, protocol, sampling and actual
Popen/wait handling are unchanged. A new formal attempt must obtain eight real
worker exit0 receipts and actual evaluator parent0/full release; it is never
selected by comparing its performance with the failed attempt.

## Preserve the failed attempt before resume

`preserve.py` requires an independently published immutable plan with schema
`opsd-signal-evaluation-preservation-plan-v2` and fields `helper_root`,
`source_manifest`, `publication`, `source_commit`, `config` (original G_POS),
`failure_metadata` (a337), `destination`, `output`, and `mutable_metadata`.
`destination` is a new directory below the remote study `preserved/`; `output`
is a new mapping receipt below `receipts/`. No existing target is overwritten.

`mutable_metadata` is exactly four explicit fresh path/SHA refs: original group
`runs/status.json`, `runs/failure-actual-exits.json`, study `study-status.json`,
and original group `receipts/scoped-cpu-processes.json`. The first two must
match the recorded failure metadata. These files would be overwritten by the
unchanged native resume, so their original bytes are copied to a new metadata
sibling directory before resuming. The failed canonical `evaluations/outer-15`
tree, including old request, logs, traces, shards and original worker files,
is inventoried with fresh streaming SHA and renamed to the new preserved
directory. Every mapped file is then fresh-hashed at its new location.

The accepted `opsd-signal-failed-evaluation-preservation-v2` output contains
`files` (the complete old-tree mapping), `metadata_files`, counts and hashes.
Old JSON absolute paths are not rewritten: all consumers of the old failure
must resolve them through this immutable original-to-preserved mapping. Newly
created canonical outputs are a different attempt and cannot be substituted
for old refs. A before-rename proof is also retained. A crash after rename is
not accepted and must be handled by a separate audited repair, never overwrite
the destination or rerun preservation blindly.

Both preservation and recovery guard verify actual old owner/worker absence,
only the admitted GPU7 oracle, four GPU UUIDs/free memory, original source and
publication. Original observer admission remains strict (the currently live
observer is reused). The startup guard freshly hashes source100 all12 files,
runtime305, train/validation/common initial and complete CP150 payload. Those
are fresh launch checks, not claims made from the old metadata-only snapshot.

Remote CLI, using the original environment/UID1001 and empty CUDA visibility:

```text
ORIGINAL_PYTHON -B NEW_HELPER/preserve.py --plan PLAN --plan-sha256 PLAN_SHA
ORIGINAL_PYTHON NEW_HELPER/entry.py --mode study
  --recovery-ref REPAIR --recovery-sha256 REPAIR_SHA
  -- --study-manifest ORIGINAL_STUDY --study-manifest-sha256 ORIGINAL_SHA --resume
```

The second command uses `E1_RUN_ID=repair.supervisor_run_id`,
`PYTHONDONTWRITEBYTECODE=1`, `PYTHONUNBUFFERED=1`, and
`CUDA_VISIBLE_DEVICES=''`. The wrapper preserves the original explicit GPU
environment for later trainer/worker children. No local checkpoint, raw
trajectory, full evaluation or tensor transfer is needed.
