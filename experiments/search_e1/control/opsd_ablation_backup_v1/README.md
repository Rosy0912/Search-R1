# Explicit checkpoint backup, CPU candidate

This independent stdlib entry copies the reviewed pinned-backup USTAR/fixed-handle/safe-extraction implementation. It does not import, modify, deploy or run the old backup namespace or science helpers. No Torch, model, optimizer, RNG restoration, GPU setup, signal or node write is performed. Inventory and stream are read-only HKUST1 commands; only the Mac backup mode starts SSH and writes a fresh local private directory. This candidate has only been exercised on synthetic local CPU files.

Every invocation explicitly binds config path/SHA, checkpoint manifest path/SHA, run, optimizer updates, outer, current goal receipt path/SHA, new helper manifest path/SHA, publication receipt path/SHA and published commit. There is no latest inference. Remote real/effective UID must both be 1005; only the hkust1 alias is accepted. Existing destination and extraction roots are rejected; newly created roots use mode0700. The exact original 18 members are checkpoint manifest, eight rank states, three adapter files (including README), four training inputs, original config, original run identity. New ablation checkpoints may explicitly reference one shared_optimizer reference to canonical optimizer-shared.pt with optimizer_storage=shared_exact_eight_rank_optimizer_v1 in the checkpoint directory, making exactly 19 members; all eight declared optimizer tensor digests must match and the actual additional file receives full SHA/stat checks. Old CP374 cannot add this shared format. This is file transport, not a CPU tensor audit. Fresh full SHA and stable stat/fixed-handle checks apply to all transferred files; symlink components, inode aliases, unexpected/special/duplicate/PAX/GNU members and trailing nonzero archives are rejected. Local extracted files receive a second complete disk SHA read. Only actual transfer rc0 plus this readback can publish complete-sha-verified.json. Failed/partial outputs remain; no remote originals or old backups are removed.

## Goal receipt contract

The receipt is an explicit controller/publisher input, not generated by this backup tool. Its top-level fields are:

```json

  "accepted": true,
  "goal_created_unix": 1791472699,
  "goal_scope": "ablation-final10",
  "variant": "C0",
  "run_id": "EXACT_CONFIG_RUN",

  "outer_index": 9,
  "config": {"path": "/EXACT/NODE/config.json", "sha256": "EXACT_SHA256"},
  "checkpoint": {"path": "/EXACT/NODE/checkpoints/update-00000091-outer-00009/manifest.json", "sha256": "EXACT_SHA256"},
  "final_completion": {"path": "/EXACT/NODE/outers/outer-00009/training/outer-complete.json", "sha256": "EXACT_SHA256"},
  "source_job_exit": {"classification": "NOT_AUDITED_BY_BACKUP"}
```

The example counters/path are illustrative, never defaults. New targets allow only C0/C1/M/R/W/P/J and outer9; actual config must have 10 outers and checkpoint's reverse direction/variant/precision/mixture/common-init contract must match. Freshly read native final completion must bind the exact selected CP and supplied updates. The caller must obtain those updates from the accepted native outer chain; this transfer helper does not repeat the full ten-outer science/tensor audit. A K0 completion pointing to an earlier canonical CP is HOLD/unsupported here; it must not be relabeled as a fabricated outer9 checkpoint.

For old CP374 use goal_scope=old-online374, exact run1d1d67b60f0e46a2afc0536a36ab69b1/update374/outer37, manifest SHA14278230c81774f271679a5345828213b2d57929887341ffcca9e41e2af28b40. No source-job rc0 is inferred from backup success.

Goal and final/stop evidence JSON identities are preserved in the local inventory/complete receipt, separate from the 18-file payload. The Mac local goal copy and its node copy must be byte identical but may have different paths. The goal is SHA-bound input scope, not evidence of numerical Adam equality, convergence, 200 completion, benchmark effect or deployment acceptance. Only the stop receipt contents/final completion binding specified above are independently read here.

## Interface

After root publication/deployment/readback (not performed by the author), run local backup.py backup with all these explicit flags:

```
--config NODE_CONFIG --config-sha256 CONFIG_SHA
--checkpoint NODE_CP_MANIFEST --checkpoint-sha256 CP_SHA
--expected-run RUN --expected-updates UPDATES --expected-outer OUTER
--goal-identity LOCAL_GOAL --remote-goal-identity NODE_GOAL --goal-identity-sha256 GOAL_SHA
--source-manifest LOCAL_HELPER/source-manifest.json --source-manifest-sha256 HELPER_SHA
--publication LOCAL_PUBLICATION --remote-publication NODE_PUBLICATION --publication-sha256 PUBLICATION_SHA
--source-commit COMMIT --remote-helper-root NODE_HELPER --destination NEW_PRIVATE_MAC_DIR
```

Each new publication receipt binds the selected expected run and fresh helper payload hashes under experiments/search_e1/control/opsd_ablation_backup_v1/. Remote inventory/stream take the same exact arguments except local destination/remote mirrors; stream accepts only the accepted inventory JSON on stdin and emits only USTAR on stdout. The helper starts no node process other than its read-only SSH entry; transfer actual rc is saved immediately after wait independently of subsequent artifact hashing/flush success, no other process is signaled.
