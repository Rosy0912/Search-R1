# Read-only experiment monitoring

`archive_readonly_snapshot.py` records the existing HKUST4 archive experiment's node, own-UID processes, GPU4–7 inventory, logs, checkpoints, observers and five correctly mapped frozen source trees. The first actual use on 2026-10-08 18:19 CST read GRPO171, ongoing172, healthy observers and matching source files. It did not start, stop, modify or recover a training process.

The script is designed to be supplied on stdin to the existing authorized `hkust4` SSH connection using the system Python and `PYTHONDONTWRITEBYTECODE=1`. It prints a private JSON snapshot to stdout; save that outside Git on the local host. It does not import a model, initialize CUDA, perform HTTP retrieval, write node files or send process signals. GPU inventory output covers only the archive's authorized GPU4–7. Process selection is limited to UID1001 and the existing run or experiment/retriever paths; only explicitly selected experiment environment keys are included.

The snapshot is evidence collection, not a training success gate. Parser errors or races must be investigated separately from actual job failures. It checks each source file against its actual manifest; root must also compare the manifest SHA to the frozen identity. Checkpoint paths/file counts are recorded without rehashing large model weights. Native validation values remain the original rounded log metrics unless independently re-evaluated. Historical observer fields derived from total-minus-used must not be described as direct `memory.free`; current `nvidia-smi` samples are recorded separately.

Do not commit snapshots, raw process/log outputs, questions, trajectories, token logs, weights, environments or credentials. The original node runtime is unchanged. This file preserves the exact helper used for the check and is not an authorization to restart, alter or stop the archive experiment.

`read_cp31_cpu.py` preserves the separate HKUST1 read-only audit of the permanently retained online OPSD CP31/outer2. It requires the frozen run/config/source/checkpoint identities and an explicitly empty CUDA mask. Supply it on stdin to the existing authorized HKUST1 environment Python with `PYTHONDONTWRITEBYTECODE=1`; it imports Torch only to read already committed, SHA-bound states on CPU. It does not load a model, create an optimizer, restore global/production RNG, write node outputs, perform HTTP, initialize CUDA or send signals.

Its scope is eight full actual Adam states and the adapter versus retained CP5, all292 token-log path/size inventory and native summary checks, and the four update31 tail trajectories' complete token records. It does not re-evaluate logits or all earlier token records. The expected current-status path is `runs/status.json`; the initial read-only attempt's wrong status path and stderr were kept privately. That tooling error did not indicate a training failure. This fixed-identity helper must not be reused to infer a different checkpoint's state or a performance gain.

`read_checkpoint_cpu.py` is a reusable independent CPU audit of an explicitly selected, committed checkpoint from the same online implementation. Supply all eight identity arguments: `--config`, `--config-sha256`, `--checkpoint`, `--checkpoint-sha256`, `--expected-updates`, `--expected-outer`, `--baseline-checkpoint`, and `--baseline-sha256`. Bind these to freshly checked immutable artifacts; the tool does not select a mutable latest pointer. Run the published source on stdin using the authorized node environment Python, `CUDA_VISIBLE_DEVICES=''` and `PYTHONDONTWRITEBYTECODE=1`. It verifies all helper source files before executing those exact files without cached bytecode. Zero-pair or uncommitted-update states require a separate audit and are explicitly unsupported here.

The reusable reader loads all eight actual Adam states on CPU through SHA-bound file handles and checks finite moments, identical rank states/groups, real step counts, adapter identity and changes versus the explicit baseline. It checks the current outer's update summaries, shuffled order, pair provenance and all token-log file metadata. It reads every token record only in the latest committed mini batch, reconstructing the frozen policy mask from recorded IDs/offsets and checking trajectory means and the actual tail-batch denominator. It does not recompute tokenizer outputs, logits, prefix encodings or historical full-vocabulary arrays. Source100's manifest and twelve-file inventory are bound and checked for metadata continuity; this reader does not rehash the large source weights. The baseline adapter is read, but its Adam states are not reread. Fresh source-weight identity checks and live process/memory checks remain separate monitoring evidence.

`test_read_checkpoint_cpu.py` exercises real tiny Torch CPU state reads, identity and inode failures, moment/rank mismatches, source-only imports, unsupported states, native frozen-mask behavior and actual tail denominators. Passing these fixtures validates the reader implementation; a real node audit is required before claiming that any target checkpoint passed. Neither the tests nor a successful state audit establishes an EM improvement.

`online_readonly_snapshot.py` checks the current HKUST1 online200 run through explicit immutable config and controller-binding paths and SHA256 arguments. Run the published source on stdin to the original environment Python with an empty CUDA mask and bytecode writes disabled. It validates the unchanged scientific config, freshly hashes all305 runtime files, all twelve source100 files and both datasets, verifies the original23 helper files plus the exact wait/CPU-merge recovery source and publication chain, and checks actual controller identity. Large source weights are streamed without keeping their bytes.

Live evidence includes current stage and sampling counts, completed-outer count and actual-update/exposure totals, the latest completed checkpoint's fresh file hashes, latest committed scalar summaries, own descendant GPU inventory, actual free memory, the original observer and the admitted oracle's health. This helper performs only a `/health` request, no retrieval or model call. It does not load Adam tensors or re-evaluate historical token losses; use the separate committed-checkpoint reader for that evidence. A changed mutable receipt, partial sampling line or source/process read uncertainty is recorded as uncertainty and must not be called a training failure. Current immutable source/config failure likewise requires a separate inspection of the actual job.

Its ten CPU fixtures include identity/schema failures, ownership and memory boundaries, source-only imports and actual locally retained config/publication/observer field compatibility. The private fixture explicitly translates local paths and uses its receipt-time clock; it is historical schema evidence, not a claim about current node health. Tests fail when that explicitly required private fixture is missing. No private fixture or snapshot is copied into Git.
