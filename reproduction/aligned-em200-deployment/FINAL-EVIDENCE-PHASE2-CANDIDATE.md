## Two independent evidence stages

`hash` takes an immutable successful partial `phase1-evidence.json`, the actual new formal submit receipt, a clean source080 checkout and a fresh completed terminal scheduler observation. Before large reads it rebinds the entire original phase1 report, all original raw records, their independent archived copies, original formal tool/receipt/helper bytes, source/RUN/job identity and reference4000 accounting. Changed inputs or pending jobs are refused. The raw scheduler query is saved before interpretation; exceptions retain original reports, completed inventories and traceback. All output files and directories are exclusive.

The hash stage resolves the fixed reviewed borrowed official model directory, verifies its pinned official manifest and hashes all12 listed assets. It records dev/inode/size/mtime/ctime before/after the single full official byte scan. At each outer5/50/100/150/200 it inventories and fully hashes every file under actual `checkpoints/actor/global_step_N`, `checkpoints/fresh200_state/outer_N_COMPLETE` and `checkpoints/algorithm/global_step_N`. It requires HF12-file coverage, driver/status/reload/ledger and all eight native shards/sidecars, refuses symlinks/special/hardlinked/foreign-owner files, and verifies directory membership remains identical. These are **derived collector hash inventories**, not fabricated source-written native manifests or subsequent GPU roundtrips. Every completed inventory is written separately, so later failure preserves the completed work.

`hf` takes the original hash-stage `phase2-evidence.json` and the same original phase1 path in a new unused evidence directory. Source/job/submission/report identities must match. It rebinds phase1 original records and archived copies again, binds/rechecks the original hash-stage report and its exact helper bytes, and checks all previously fully hashed originals still have identical device/inode/size/mtime/ctime and exact directory membership. This is a recorded metadata-based continuation boundary; it does not claim another full SHA scan occurred, and any changed fingerprint requires recollecting the hash evidence. No stale result is accepted merely because its filename exists.

CPU HF work actually loads the official model and every one of the five HF exports offline with eager attention, verifies loading diagnostics, exact official Qwen2.5-3B dimensions/count, actual tied storage, **all loaded parameters** finite and CPU-resident, and an actual finite CPU forward. Each export uses the reviewed first5 tokenizer proof, comparing full vocabulary/special-token/added-token/chat metadata and actual chat tokenization against the official tokenizer. The reviewed weight scan reads all official/export tensors, applies the base-to-export dtype cast before computing complete float64 difference statistics, and rejects rounding-only or a nonfinite later tensor. It is not a first changed witness or a chunk-only finite check. Completed official/per-export CPU results are saved separately. Input fingerprints, inventories, original reports and helper bytes are checked again after costly work.

The evidence can continue from completed hash to HF without repeating all large SHA reads. Fine-grained automatic reuse of a partly completed HF invocation is not implemented; completed checkpoint result files are preserved for independent review, and a rerun uses a new exclusive output. These evidence stages are unrelated to training resume, which this tool cannot perform.
