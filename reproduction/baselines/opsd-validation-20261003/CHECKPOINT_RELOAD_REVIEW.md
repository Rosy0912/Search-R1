2. **Index equality does not prove actual shard completeness.** `mapping()` trusts the index `weight_map` without opening all referenced files. A stale index may list tensors missing from its shard, or leave extra unexpected shard tensors. `from_pretrained` normally reports missing weights and initializes them; finite logits are not a sufficient rejection. Open each declared shard, validate actual keys against the index, and verify every expected nonalias tensor is present with expected shape (and preferably finite). Load using `output_loading_info=True`; explicitly reject nonempty `missing_keys`, `unexpected_keys`, `mismatched_keys`, `error_msgs`. The probe removed an actual q_proj tensor and demonstrated a finite forward with a nonempty missing-keys report. A complete structural config comparison against the fixed base must also guard changed architecture/tie semantics; ignore only documented provenance/runtime serialization fields.

3. **Tokenizer identity is weaker than the claimed identity.** Equal vocabulary plus BOS/EOS/PAD IDs does not guarantee equal normalization, pretokenization, postprocessing, added/special token behavior, or chat template. Compare canonical parsed tokenizer backend JSON and the effective added/special token settings and chat template. Account for legitimate save metadata/path changes rather than comparing all tokenizer files byte-for-byte.
