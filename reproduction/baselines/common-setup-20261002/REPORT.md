# Common deployment adaptation — 2026-10-02

Frozen baseline: 0723dca0c1458482ac3e78f8ed43af04893955d2; this branch inherits the six-agent plan commit 1620c2e.

Implemented user-approved deployment changes: GPU eligibility uses both occupancy thresholds ≤15%, retaining process inventory, UUID leases and startup recheck; invalid/nonfinite occupancy fails closed. The asset preparation helpers accept explicit asset/repository roots. Retrieval accepts encoder CPU device, CPU FAISS, host/port and thread budget while preserving the original CUDA/FP16 defaults. NCCL rank-sum check uses actual world size. Split manifests add path-independent source/content/question/row identity without changing split mathematics.

Smoke-only runs are restricted to at most five outer updates and skip only terminal final-set evaluation. Formal runs retain seven-set final evaluation. Validation now reports sample-weighted generated-answer F1/EM, answer-tag rate, complete action-format rate, search tags and generated tokens, without observing prompt/observation answers. These additions do not alter training reward.

Teacher evaluation uses `run.sh grpo` with `baselines.holdout_eval_only=true trainer.val_only=true trainer.val_before_train=true baselines.holdout_record_path=<new-record> actor_rollout_ref.model.path=<global_step_N/actor>`. Keep original source training/periodic/final paths to construct the common split; the driver switches evaluation to holdout after that split. No validation subsampling is allowed. Only updates 5/100/200/300/400/500 are accepted. The completed real evaluation produces records bound to checkpoint hash, split identity, seed42 and exact holdout count. Combine the six record objects into a JSON list, then call `python -m search_r1.baselines.select_teacher --records <list.json> --split-manifest <manifest.json> --student <base-model> --destination <new-immutable-dir>`. The selector verifies split output hashes, candidate HF hashes, actual weights and shards, tokenizer vocabulary/BOS/EOS, changed student weights; highest F1 wins, ties earliest update. It never reads final-test question data for ranking. Original final/periodic inputs are read only to exclude overlap when defining the split.

Independent reviewer `review_common` found and verified repairs for missing evaluation-record binding, index-only teacher acceptance, and an AST regression fixture. Complete CPU gate: 139 passed / 1 skipped (Linux procfs unavailable on macOS). Final guard rejects missing/existing record destinations before expensive evaluation.

Not yet accepted: Linux pinned dependency imports, real CPU E5/index versus original GPU top3/top50 rankings/scores, retrieval throughput/RAM, GPU/NCCL/Flash/vLLM integration, 3B smoke, training, teacher quality and final benchmark effects. CPU success is not production or metric reproduction success. Full optimizer/RNG/dataloader exact resume remains unsupported. GiGPO joint textual-action ratio remains intentionally different from author token-PPO; no algorithm mathematics changed here.
