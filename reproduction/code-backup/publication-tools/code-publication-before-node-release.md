## 强制规则

- 所有实验的最新实现、训练与推理入口、部署/启动/恢复脚本、评分实现、运行所需配置和依赖说明，都必须进入 Git 并推送到用户指定远程。只提交核心算法、遗漏仓库外运行脚本，视为未完成代码备份。
- 完成一项实际实现或修复后，及时提交并推送。远端节点上的修改须先同步到持久本地副本并核对文件哈希，不能只留在节点临时盘或任务目录。
- 本地 commit、旧 GitHub 分支存在、过去某次成功 push、工作目录干净，均不能替代“最新实现已完整推送”的证明。必须绑定当前实际源码 commit 和部署文件版本。
- 主动释放本任务节点、销毁工作区、删除本任务源码或进行可能导致临时文件丢失的操作前，必须先完成提交、推送及远程核验。调度器可能自动到期释放节点，应提前保存代码，而不是等终态后才备份。
- 推送后读取远程分支 SHA，必须等于本次提交；再通过 Git 读回或远端仓库下载核对实现文件清单及 SHA256，记录 session、源码 commit、备份分支、最终远程 commit、校验时间、未覆盖项。
- Git 仓库外的运行工具必须入库，记录原始相对目录与用途；候选、历史和已部署版本分清，不把备份目录内的提交脚本视为重新运行的授权。
- 保护其他会话正在使用的 checkout：必要时在独立复制目录和独立分支整理备份，不切换或重置原 checkout，不停止训练，不热改运行源码，不向其他 agent 发送消息，除非用户另行授权。
- 凭据、令牌、私钥、环境目录、模型权重和数据集不得混入代码提交；权重按独立迁移授权处理。发布前检查新增内容及未发布历史是否带凭据。
- “强制提交”指必须执行提交和推送，不是允许 `git push --force`。保留历史分支和提交，不能用覆盖远程历史来掩盖遗漏。
- 连接/权限阻塞时保留持久本地副本和待推清单，向本线程明确报告“尚未推送/尚未核验”；禁止把失败或无法核实写成全部已备份。
